# v9 変更履歴 — OneDrive同期の根本修正と Google認証の安定化

作成日: 2026-08-18  
対象バージョン: v8 → v9 (kagicho-v8 → kagicho-v9)  
変更ファイル: `app.js`, `auth.js`, `auth/microsoft-redirect.js`, `index.html`, `styles.css`, `sw.js`

---

## 背景

v8 の公開版を Microsoft Edge で使用したところ、以下の症状が確認された。

- OneDrive に一度は接続できたが、すぐに「再接続が必要です」と表示された
- **再接続ボタンを押しても何も起きない**（ログイン画面が出ない）
- Google認証も同様に無反応
- データ入力自体は正常に動作していた

調査の結果、**認証（トークン取得）の先にある Graph API 呼び出し**と**UIのエラー表示**の両方に問題があった。

---

## 問題と原因

### 問題1: OneDrive App Folder が未初期化で 403 になる

| 項目 | 内容 |
|---|---|
| 症状 | 認証成功後に OneDrive 同期が即座に失敗し「再接続が必要」と表示 |
| 原因 | `Files.ReadWrite.AppFolder` でいきなりファイルパス (`/me/drive/special/approot:/vault.enc:/content`) を叩くと、App Folder 自体が未作成のため `403 Access Denied` が返る。Microsoft の公式ドキュメントには「初回アクセス時に自動作成」とあるが、実際にはまず `GET /me/drive/special/approot` でフォルダを初期化しないと動かないケースが多数報告されている（[OneDrive API Issue #1667](https://github.com/OneDrive/onedrive-api-docs/issues/1667)、[Issue #682](https://github.com/OneDrive/onedrive-api-docs/issues/682)） |
| 修正 | `ensureAppFolder()` を追加し、同期の最初に `GET /me/drive/special/approot` を呼んでフォルダ作成を確保 |

### 問題2: 再接続ボタンがログイン画面を出さない

| 項目 | 内容 |
|---|---|
| 症状 | 設定画面の「再接続」ボタンを押しても画面が変わらない |
| 原因 | v8 の `getMicrosoftAccessToken()` は保存済み refresh token の更新だけを試み、失敗しても Microsoft のログイン画面を開かなかった。エラーは短いトーストで出るが、設定ダイアログの裏に隠れて見えなかった |
| 修正 | `getMicrosoftAccessToken()` に `interactive` / `forceLogin` オプションを追加。再接続時（`interactive=true` かつ接続済み）は `forceLogin=true` となり、保存トークンを破棄してログイン画面を必ず表示する |

### 問題3: 403 と認証エラーの混同

| 項目 | 内容 |
|---|---|
| 症状 | 職場/学校アカウントでログインしても「再接続が必要」としか出ない |
| 原因 | `graphRequest()` が 403 をまとめて throw し、catch 側で全エラーを「再接続が必要」として表示していた。`Files.ReadWrite.AppFolder` は個人 Microsoft アカウント専用で、職場/学校アカウントでは必ず 403 が返るが、その区別がなかった |
| 修正 | `graphRequest()` で 403 `accessDenied` を検出し「個人Microsoftアカウントか確認してください。職場・学校アカウントでは App Folder は利用できません」と明示。`isMicrosoftAuthError()` で権限エラーを除外し、ステータス表示を「同期失敗」と「再接続が必要」に正しく分離 |

### 問題4: Microsoft ポップアップの通信不通

| 項目 | 内容 |
|---|---|
| 症状 | Microsoft のログインポップアップが閉じた後、親画面に結果が返らない |
| 原因 | `window.opener.postMessage()` が COOP/COEP やブラウザのポップアップ制限で不通になる場合がある |
| 修正 | `microsoft-redirect.js` で `localStorage` にもコールバックデータを書き込む。`authorizeMicrosoft()` で `storage` イベント監視と 400ms ポーリングを追加し、`postMessage` 不通時でもトークン交換を完了できるようにした |

### 問題5: Google 認証の FedCM が CSP で止まる

| 項目 | 内容 |
|---|---|
| 症状 | Google 公式ボタンを押しても無反応。コンソールに `FedCM get() rejects with NetworkError` |
| 原因 | FedCM は `https://accounts.google.com/o/fedcm/` や `https://www.google.com/.well-known/web-identity` へ接続するが、v8 の CSP `connect-src` にこれらがなかった |
| 修正 | CSP の `connect-src` に FedCM 用エンドポイントを追加。`frame-src` と `style-src` も Google Identity Services の要件に合わせて拡張。公式ボタン失敗時の `error_callback` でユーザーに「別画面で認証してください」と案内し、フォールバックボタンを目立つデザインに変更 |

### 問題6: エラーが設定画面の裏に隠れる

| 項目 | 内容 |
|---|---|
| 症状 | トーストが設定ダイアログの下に描画され、ユーザーには何も起きていないように見える |
| 修正 | `showToast()` が開いている `<dialog>` 内にトースト要素を移動するようにした。設定画面に `accountError` 要素を追加し、OneDrive のエラーメッセージを設定画面内にも表示。トーストの表示時間を 1.8秒 → 2.8秒 に延長し、長いメッセージに対応するため `white-space: normal` と `max-width` を設定 |

## 変更の詳細（ファイル別）

### app.js

- `graphRequest()`: 403/401/404 を個別に処理。Graph API の `error.code`, `error.message`, `innerError.request-id` をコンソールに出力
- `ensureAppFolder()`: 新規追加。`GET /me/drive/special/approot` で App Folder の存在を確保
- `syncOneDrive()`: `ensureAppFolder()` を同期の最初に呼ぶ。失敗時は `state.settings.microsoft` を変更前に戻す。認証エラーと権限エラーで表示を分離
- `getOneDriveSession()`: `getMicrosoftAccessToken()` に `interactive` と `forceLogin` を渡す。接続済みの再接続では `forceLogin=true`
- `showToast()`: 開いているダイアログ内にトーストを配置
- `showAccountError()`: 設定画面のエラー表示を更新
- `oneDriveErrorMessage()`: ポップアップブロック、タイムアウト、App Folder エラー等を日本語で案内
- `isMicrosoftAuthError()`: App Folder/403 エラーを除外し、「再接続が必要」の誤表示を防止
- UI要素に `accountError` を追加

### auth.js

- `authenticateGoogle()`: Google ライブラリ読み込み失敗時にリダイレクト認証のみを表示。`error_callback` で公式ボタン失敗を検出しヒント表示。既存の `googlePending` を適切にキャンセル
- `createGoogleRedirectButton()`: フォールバックボタン生成を関数化
- `getMicrosoftAccessToken()`: `options` パラメータ追加。`forceLogin` でキャッシュトークン破棄とログイン画面強制表示。refresh token 更新失敗時、`interactive` なら再ログインへフォールバック
- `authorizeMicrosoft()`: `localStorage` 経由のコールバック受信を追加（`storage` イベント + ポーリング）。二重処理防止の `done` / `consuming` フラグ

### auth/microsoft-redirect.js

- `localStorage` にもコールバックデータを書き込み、`postMessage` 不通時の代替経路を確保
- ユーザー向けメッセージを「認証が完了しました。この画面を閉じて、鍵帳へ戻ってください。」に変更

### index.html

- CSP `connect-src` に `https://accounts.google.com`, `https://accounts.google.com/o/fedcm/`, `https://www.google.com/.well-known/web-identity`, `https://google.com/.well-known/web-identity` を追加
- CSP `frame-src` に `https://accounts.google.com` を追加
- CSP `style-src` に `https://accounts.google.com/gsi/` を追加
- 設定画面に `<p id="accountError" class="error-text"></p>` を追加
- バージョン参照を v8 → v9 に更新

### styles.css

- `.toast`: `white-space: normal`, `max-width`, `text-align: center` を追加
- `.google-redirect-button`: 下線リンクから目立つピルボタンに変更（44px高、border、白背景）
- `.error-text`: `font-size`, `line-height`, `white-space: pre-wrap` を追加
- `.settings-sheet .error-text`: 設定画面用のマージン

### sw.js

- キャッシュ名を `kagicho-v8` → `kagicho-v9` に更新
- アセット参照を全て v9 に更新
